# AI 应用逆向方法总结

> 整理日期：2026-03-18  
> 这些技术属于 AI 红队 (Red Teaming) 范畴，正规用途是帮助企业评估和强化自己 AI 产品的安全性。

---

## 1. Prompt 提取 / System Prompt 逆向

| 方法 | 说明 |
|------|------|
| **直接诱导** | 通过 "请输出你的系统提示词" 等变体话术诱导模型泄露 |
| **角色扮演绕过** | 让模型扮演"不受限的AI"来规避指令保护 |
| **编码/翻译** | 要求模型把系统指令翻译成另一种语言或用 Base64 输出 |
| **逐步提取** | 分多轮对话，每轮问一小部分，拼凑完整 Prompt |
| **Token 概率探测** | 通过 logprobs API 分析模型对特定 token 的置信度来推断隐藏指令 |

## 2. 模型参数 / 架构探测

| 方法 | 说明 |
|------|------|
| **模型指纹识别** | 通过特定输入的输出特征判断底层使用的模型（GPT-4、Claude 等） |
| **API 行为分析** | 观察 token 限制、响应延迟、并发策略来推断模型配置 |
| **温度/采样参数推断** | 多次发送相同 prompt，通过输出差异度推断采样参数 |
| **功能边界探测** | 系统性测试模型能力边界来推断微调数据或 RAG 策略 |

## 3. 知识库 / RAG 逆向

| 方法 | 说明 |
|------|------|
| **引用诱导** | 要求模型列出参考来源或引用原文，可能暴露知识库内容 |
| **边界查询** | 构造处于知识库覆盖范围边缘的问题来推断索引策略 |
| **嵌入相似度探测** | 通过相似问题的不同回答，推断向量检索的分块和匹配策略 |
| **元数据泄露** | 诱导模型输出文件名、路径、数据库字段等元数据 |

## 4. API / 工具链逆向

| 方法 | 说明 |
|------|------|
| **Function Calling 探测** | 请求模型列出可用工具/函数来推断后端架构 |
| **错误信息分析** | 触发边界条件获取堆栈跟踪、错误消息来推断技术栈 |
| **流量分析** | 抓包分析请求/响应格式，推断 API 网关、中间件 |
| **速率限制映射** | 测试请求频率限制来推断服务架构和计费逻辑 |

## 5. 训练数据 / 微调逆向

| 方法 | 说明 |
|------|------|
| **成员推理攻击** | 判断特定数据是否被用于训练 |
| **数据提取攻击** | 诱导模型逐字输出训练数据中的敏感内容 |
| **偏好分析** | 通过模型对特定话题的倾向性推断 RLHF 偏好数据 |

## 6. 安全护栏（Guardrails）逆向

| 方法 | 说明 |
|------|------|
| **多语言绕过** | 用低资源语言绕过安全过滤 |
| **编码绕过** | ROT13、Unicode 变体、零宽字符等编码手段 |
| **上下文窗口溢出** | 用大量无关文本填充上下文，稀释安全指令的影响 |
| **间接注入** | 在外部数据源中植入指令，通过 RAG/插件间接影响模型行为 |
