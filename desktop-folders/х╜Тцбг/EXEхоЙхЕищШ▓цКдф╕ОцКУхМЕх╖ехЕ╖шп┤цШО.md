# EXE 客户端安全防护与抓包工具说明（概要）

本文档面向 Windows EXE 客户端，目标是降低注入、逆向与抓包风险。核心原则是“提高攻击成本 + 及时检测 + 服务端兜底”，而不是追求绝对阻断。

## 1. 边界与前提

- 用户设备由用户完全控制，无法在客户端侧彻底禁止抓包或逆向。
- 防护的正确目标是：提高成本、降低可行性、增加检测与追责能力。
- 任何关键安全逻辑必须在服务端验证，不可仅靠客户端。

## 2. 多层防护建议（按优先级排序）

**2.1 通信与加密**

- 强制 TLS 1.2/1.3，禁用弱加密套件。
- 证书固定（Certificate Pinning），拒绝非可信证书链。
- 支持 mTLS（双向证书），在高风险场景仅允许可信客户端接入。
- 请求级签名（HMAC/ED25519）+ 时间戳 + nonce，防止重放。
- Token 短生命周期 + 轮换机制，避免长期滥用。

**2.2 客户端二进制加固**

- 启用编译/链接安全开关（ASLR/DEP/CFG/CET）。
- 代码签名，提升篡改门槛并便于识别篡改版本。
- 关键模块完整性校验（哈希/签名），检测篡改与注入。
- 适度混淆或虚拟化保护关键逻辑，减少静态分析效率。

**2.3 反注入与反调试**

- 检测常见调试状态与挂钩迹象（仅用于风险评估或降级）。
- 对高敏感流程采用“失败即降级/拒绝”的策略。
- 防 DLL 劫持：固定 DLL 加载路径，开启安全搜索路径。

**2.4 机密与凭证保护**

- 客户端不内嵌长期密钥；关键密钥下沉至服务端。
- 本地敏感数据使用系统安全存储（例如 DPAPI）。
- 只在内存中短时使用密钥，避免落盘。

**2.5 服务端兜底**

- 关键逻辑必须服务端校验（权限、限额、签名、重放）。
- 行为风控：速率限制、设备指纹、异常模式检测。
- 审计与告警：异常调用、可疑请求来源自动告警。

**2.6 发布与更新安全**

- 更新包签名 + 校验，阻止中间人替换。
- 版本回滚保护，防止加载旧版本漏洞。

## 3. 常见抓包工具（市场主流）

- Wireshark（网络协议分析）
- Fiddler（HTTP/HTTPS 调试代理）
- Burp Suite（Web 安全测试/代理）
- Charles Proxy（HTTP/HTTPS 代理调试）
- mitmproxy（命令行代理）
- tcpdump（命令行抓包工具）

## 4. “禁用抓包”现实结论

- 客户端无法从根本上禁用抓包，因为用户掌控系统与网络。
- 正确策略是“识别风险 + 降级或拒绝高风险请求 + 服务端验证”。
- 依赖证书固定与 mTLS 可大幅提高抓包与中间人难度，但仍无法做到绝对阻断。

## 5. 最小可落地清单（建议先做）

- TLS 1.2/1.3 + 证书固定
- 请求签名 + 防重放（nonce/时间戳）
- Token 短期化 + 轮换
- 启用 CFG/ASLR/DEP/CET
- 更新包签名与完整性校验
- 服务端风控与异常告警
